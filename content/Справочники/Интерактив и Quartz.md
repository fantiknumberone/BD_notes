# ⚡ Интерактив и Quartz

[[index]] · [[Практика/Учебный набор]] · [[Практика/SQL-практикум]]

## Принцип хранения

Все задания — обычные fenced-блоки Markdown с маркером на первой строке. В Obsidian они видны как код и редактируются без дополнительных плагинов. На Quartz клиентский компонент превращает их в виджеты. Бэкенда, подключения к пользовательской PostgreSQL и отправки ответов на сервер нет.

Подготовлен пакет `quartz-support/` под предложенную структуру **Quartz 4**: `quartz/components`, экспорт в components/index.ts, `afterBody` в quartz.layout.ts и событие `nav`. В папке BD\_rep нет существующего проекта Quartz, поэтому готовые исходники лежат отдельно и ещё не подключены к опубликованному сайту. У Quartz 5 другой способ упаковки компонентов; для него потребуется адаптация подключения. Содержимое заметок и формат блоков от этого не зависят.

## Пять маркеров

Ниже показан синтаксис как текст с отступами, чтобы примеры документации сами не превратились в дополнительные задания.

**setup:** первая строка `-- setup` в fenced-блоке SQL, затем CREATE/INSERT. Настройка выполняется перед SQL-виджетами; после успешной инициализации блок скрывается. При ошибке setup остаётся доступным и появляется сообщение с повторной загрузкой.

```
-- setup
CREATE TABLE sample (id INT, name STRING);
INSERT INTO sample VALUES (1, 'Пример');
```

**run:** первая строка `-- run`, затем редактируемый SQL. Есть кнопка «Выполнить», результат и обработка ошибок. Сочетание Ctrl/Cmd+Enter запускает запрос.

```
-- run
SELECT * FROM sample;
```

**quiz:** первая строка `#quiz`, вопрос `?`, один правильный вариант с `+`, остальные с `-`. Варианты перемешиваются; клик сразу показывает результат и правильный ответ.

```
#quiz
? Какая команда выбирает данные?
+ SELECT
- INSERT
- DROP
```

**order:** первая строка `#order`, затем шаги в **правильном** порядке. На странице они перемешиваются. Доступны перетаскивание SortableJS и кнопки ↑/↓ для клавиатуры и ситуации, когда CDN недоступен. При ошибке показывается исходный правильный порядок.

```
#order
Изучить правило
Написать запрос
Проверить результат
```

**task:** первая строка `#task`, далее текст задания, затем одна строка `= эталонный SQL`. Эталон нужно записать в одну строку. В интерфейсе он скрыт до неправильной попытки, но остаётся доступен в исходном Markdown страницы.

```
#task
Выведи id и name, сортируя по id.
= SELECT id, name FROM sample ORDER BY id;
```

## Как устроена проверка SQL

Сравниваются значения столбцов по позициям, а не текст запросов; алиасы могут отличаться. При наличии внешнего ORDER BY в эталоне порядок строк важен. Если сортировки нет, сравнивается мультимножество с сохранением числа повторений. Упоминание ORDER BY в строковом литерале, комментарии или вложенном запросе само по себе не включает проверку внешнего порядка.

NULL отображается отдельно от нуля и пустой строки. Числа сравниваются с малым допуском на арифметику JavaScript. Пустые результаты сравниваются как пустые наборы; проверка не доказывает эквивалентность запросов на всех возможных данных.

В #task принимается один SELECT. В --run доступны SELECT и ограниченные операции над локальными таблицами. Внешний ввод/вывод, встроенный JavaScript и произвольные серверные расширения не входят в учебный набор. Весь SQL исполняется в отдельном Web Worker; при превышении 15 секунд worker завершается и следующая попытка может создать новый.

Каждый запуск пересоздаёт исходные таблицы из setup. Эксперимент с UPDATE в --run не изменит данные следующего задания. При SPA-переходе старый worker и Sortable-объекты завершаются, следующая страница получает собственный setup. Повторное событие nav на уже инициализированной той же статье не создаёт второй комплект виджетов.

В таблице показываются первые 100 строк; результат свыше 2000 строк ограничен сообщением. Маленькая песочница предназначена для обучения запросам, а не для оценки производительности PostgreSQL.

## Что нужно для запуска виджетов

AlaSQL 4.6.5 и SortableJS 1.15.6 загружаются с jsDelivr только на страницах с соответствующими блоками. Для первого открытия нужна сеть. На странице только с quiz внешние библиотеки не требуются. При проблеме CDN обычные заметки остаются читаемыми, а ошибки видны в виджетах.

Сайт должен разрешать загрузку скриптов с `https://cdn.jsdelivr.net` и запуск Blob Worker своей политикой CSP (`worker-src blob:` и нужные script-src). Это настройка именно хостинга; в материале нет API-ключей или серверных паролей. Успешные задания отмечаются в localStorage текущего браузера и не синхронизируются между устройствами. Очистка данных сайта сбросит этот прогресс.

## Подключение к проекту Quartz 4

1. Скопируй три файла из `BD_rep/quartz-support/quartz/components/` в одноимённые пути проекта Quartz: компонент, `scripts/interactive.inline.ts`, `styles/interactive.scss`.
2. В `quartz/components/index.ts` добавь экспорт:

```ts
export { default as Interactive } from "./Interactive"
```

3. В `quartz.layout.ts` добавь компонент в **существующий** afterBody, сохранив другие элементы:

```ts
afterBody: [Component.Interactive()],
```

В стандартном Quartz 4 это `sharedPageComponents.afterBody`. Не нужно создавать второй объект layout или удалять существующие компоненты.

4. Перенеси заметки и разрешённые вложения в content Quartz. Главную страницу можно скопировать/переименовать в `index.md` на стороне сайта. Проверь внутренние ссылки и PDF-пути после переноса.
5. Сохрани обработку Obsidian Flavored Markdown, callouts, wikilinks и Mermaid в конфигурации Quartz.
6. Собери локальный сайт по командам своего проекта и проверь страницу SQL-практикума. Затем перейди на обычную лекцию, вернись назад и проверь ещё одну попытку.

## Что исключить из публикации

В `quartz.config.ts` добавь к существующему ignorePatterns подходящие пути:

```ts
ignorePatterns: [
  ".obsidian/**",
  "quartz-support/**",
  "Шаблоны/**",
  "Дневник/**",
  "Практика/pr1/**",
  "Практика/browser-setup.sql",
],
```

Это пример дополнения конфигурации, не полный файл. Исходная папка pr1 содержит SQL и учебную Docker-конфигурацию; они не нужны для браузерных виджетов. Их можно публиковать отдельно как осознанно выбранный учебный архив. PDF lecture занимают около 155 MiB: размещение этих материалов стоит решить отдельно от текста конспекта.

Canvas и Bases нужны для работы в Obsidian. Для сайта используй Mermaid на [[01. Карта курса|карте курса]] и обычный [[Повторение/План и прогресс|чек-лист прогресса]]. Если генератор не поддерживает такие файлы, их можно исключить; текстовые маршруты останутся доступны.

## Добавление своего задания

Используй те же имена и поля набора, что описаны в [[Практика/Учебный набор]]. Убедись, что setup присутствует на странице с SQL. Эталон обязан выполняться в AlaSQL; PL/pgSQL, EXPLAIN, MVCC и утилиты резервирования оставляй обычными примерами PostgreSQL без интерактивного маркера.

> [!tip] Сначала придумай ошибочный ответ
> Хорошее задание различает понимание: отсутствие строки, NULL, повтор, одинаковые значения сортировки. Запусти правильный, эквивалентный и заведомо неверный запросы, затем проверь отображение эталона.
