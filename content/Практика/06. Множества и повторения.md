## Сравнивай множества и повторения

UNION объединяет без повторов, UNION ALL сохраняет повторения, INTERSECT оставляет общее, EXCEPT — элементы первого набора без второго. Ветви должны возвращать одинаковое число совместимых полей. Сначала найди ожидаемые ID вручную, затем проверяй запрос.

> [!info] Как решать
> На сайте введи SELECT и нажми «Проверить». При ошибке появятся эталон и его результат. Сравниваются значения и повторения строк; порядок важен, когда в эталоне есть ORDER BY. В Obsidian условие и эталон доступны в обычном кодовом блоке. Данные каждой страницы запускаются заново; решения не меняют исходный дамп.

Набор данных: [[Практика/Учебный набор]]. Все числа в проверках относятся к нему. Если хочется попробовать иной запрос, используй песочницу ниже.

> [!note] Совместимость движка
> В некоторых эталонах DISTINCT указан в обеих ветвях: это обходит особенности браузерного AlaSQL. В PostgreSQL обычные UNION и INTERSECT сами устраняют повторы. UNION ALL намеренно сохраняет их.

## Запросы с автоматической проверкой

### 01. Платили или потребляли трафик

_База._

```text
#task
Выведи уникальные subscriber_id из payments или data_usage. Порядок не важен.
= SELECT DISTINCT subscriber_id FROM payments UNION SELECT DISTINCT subscriber_id FROM data_usage;
```

> [!tip]- Подсказка после попытки
> UNION объединяет с удалением одинаковых строк.

### 02. Все упоминания

_База._

```text
#task
Объедини subscriber_id из payments и data_usage с сохранением всех повторов. Порядок не важен.
= SELECT subscriber_id FROM payments UNION ALL SELECT subscriber_id FROM data_usage;
```

> [!tip]- Подсказка после попытки
> Нельзя добавлять DISTINCT.

### 03. Платили и потребляли трафик

_База._

```text
#task
Выведи subscriber_id, встречающиеся и в payments, и в data_usage. Порядок не важен.
= SELECT DISTINCT subscriber_id FROM payments INTERSECT SELECT DISTINCT subscriber_id FROM data_usage;
```

> [!tip]- Подсказка после попытки
> Нужны общие значения двух наборов.

### 04. Платили без трафика

_Связи и условия._

```text
#task
Выведи subscriber_id из payments, отсутствующие в data_usage. Порядок не важен.
= SELECT subscriber_id FROM payments EXCEPT SELECT subscriber_id FROM data_usage;
```

> [!tip]- Подсказка после попытки
> Направление разности важно.

### 05. Трафик без платежей

_Связи и условия._

```text
#task
Выведи subscriber_id из data_usage, отсутствующие в payments. Порядок не важен.
= SELECT subscriber_id FROM data_usage EXCEPT SELECT subscriber_id FROM payments;
```

> [!tip]- Подсказка после попытки
> Поменяй местами операнды предыдущего смысла.

### 06. Без событий через разность

_Связи и условия._

```text
#task
Выведи subscriber_id из subscribers без call_records. Порядок не важен.
= SELECT subscriber_id FROM subscribers EXCEPT SELECT subscriber_id FROM call_records;
```

> [!tip]- Подсказка после попытки
> Это тот же бизнес-набор, что и корректное антисоединение.

### 07. Наборы состояний

_Самостоятельный разбор._

```text
#task
Объедини без повторов subscriber_id ACTIVE и subscriber_id с balance < 0. Порядок не важен.
= SELECT subscriber_id FROM subscribers WHERE status = 'ACTIVE' UNION SELECT subscriber_id FROM subscribers WHERE balance < 0;
```

> [!tip]- Подсказка после попытки
> Один абонент может удовлетворять обоим условиям.

### 08. Количество фактов по источнику

_Самостоятельный разбор._

```text
#task
Верни строки с source_kind = payment и COUNT(*) payments, затем source_kind = data и COUNT(*) data_usage; поле количества назови fact_count. Порядок строк не важен.
= SELECT 'payment' AS source_kind, COUNT(*) AS fact_count FROM payments UNION ALL SELECT 'data' AS source_kind, COUNT(*) AS fact_count FROM data_usage;
```

> [!tip]- Подсказка после попытки
> Совмести число и типы выходных столбцов.

### 09. Разные операции одинакового размера

_Самостоятельный разбор._

```text
#task
Верни subscriber_id и amount платежей как есть с сохранением всех строк. Порядок не важен.
= SELECT subscriber_id, amount FROM payments;
```

> [!tip]- Подсказка после попытки
> Требование всех фактов не равно требованию уникальных значений.

### 10. Только общие активные

_Самостоятельный разбор._

```text
#task
Выведи subscriber_id ACTIVE, встречающиеся в call_records, без повторов. Порядок не важен.
= SELECT subscriber_id FROM subscribers WHERE status = 'ACTIVE' INTERSECT SELECT subscriber_id FROM call_records;
```

> [!tip]- Подсказка после попытки
> Пересечение наборов не должно размножать внешний ID.

## Как проверить себя глубже

- [ ] Объяснил, что означает одна строка каждого результата.
- [ ] Предсказал хотя бы один результат до запуска.
- [ ] Объяснил роль NULL, повторений и сортировки в сложной задаче.
- [ ] Составил собственный вариант условия и проверил его в песочнице.
