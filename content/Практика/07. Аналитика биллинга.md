## От бизнес-вопроса к проверяемому отчёту

Здесь соединяются навыки предыдущих тем. Задолженность счёта, отрицательный баланс и стоимость событий — разные показатели. Не включай пополнение без invoice\_id в оплату конкретного счёта. Суммы независимых таблиц сначала собери отдельно до одной строки на ключ.

> [!info] Как решать
> На сайте введи SELECT и нажми «Проверить». При ошибке появятся эталон и его результат. Сравниваются значения и повторения строк; порядок важен, когда в эталоне есть ORDER BY. В Obsidian условие и эталон доступны в обычном кодовом блоке. Данные каждой страницы запускаются заново; решения не меняют исходный дамп.

## Запросы с автоматической проверкой

### 01. Событийная сумма для всех

_База._

```text
#task
Выведи subscriber_id и event_cost всех абонентов, заменив отсутствующую сумму 0. По subscriber_id.
= SELECT s.subscriber_id, COALESCE(SUM(c.cost), 0) AS event_cost FROM subscribers AS s LEFT JOIN call_records AS c ON c.subscriber_id = s.subscriber_id GROUP BY s.subscriber_id ORDER BY s.subscriber_id;
```

> [!tip]- Подсказка после попытки
> Зерно отчёта — абонент.

### 02. Все платежи на абонента

_База._

```text
#task
Выведи subscriber_id и paid_total всех абонентов, включая ноль. По subscriber_id.
= SELECT s.subscriber_id, COALESCE(SUM(p.amount), 0) AS paid_total FROM subscribers AS s LEFT JOIN payments AS p ON p.subscriber_id = s.subscriber_id GROUP BY s.subscriber_id ORDER BY s.subscriber_id;
```

> [!tip]- Подсказка после попытки
> Отсутствующая сумма заменяется после агрегирования.

### 03. Остаток оплаты счёта

_База._

```text
#task
Выведи invoice_id и unpaid = total_amount минус сумма связанных платежей, ноль вместо отсутствующей суммы. По invoice_id.
= SELECT i.invoice_id, i.total_amount - COALESCE(p.paid_total, 0) AS unpaid FROM invoices AS i LEFT JOIN (SELECT invoice_id, SUM(amount) AS paid_total FROM payments WHERE invoice_id IS NOT NULL GROUP BY invoice_id) AS p ON p.invoice_id = i.invoice_id ORDER BY i.invoice_id;
```

> [!tip]- Подсказка после попытки
> Сначала сформируй одну строку суммы платежей на invoice\_id, затем присоедини итог к invoices.

### 04. Счета с недоплатой

_База._

```text
#task
Выведи invoice_id, unpaid, где total_amount больше суммы привязанных платежей. По invoice_id.
= SELECT i.invoice_id, i.total_amount - COALESCE(p.paid_total, 0) AS unpaid FROM invoices AS i LEFT JOIN (SELECT invoice_id, SUM(amount) AS paid_total FROM payments WHERE invoice_id IS NOT NULL GROUP BY invoice_id) AS p ON p.invoice_id = i.invoice_id WHERE i.total_amount > COALESCE(p.paid_total, 0) ORDER BY i.invoice_id;
```

> [!tip]- Подсказка после попытки
> Сначала сформируй одну строку суммы платежей на invoice\_id, затем присоедини итог к invoices.

### 05. Средний платёж

_Связи и условия._

```text
#task
Выведи subscriber_id, payment_count и average_payment для абонентов с платежами. По subscriber_id.
= SELECT subscriber_id, COUNT(*) AS payment_count, AVG(amount) AS average_payment FROM payments GROUP BY subscriber_id ORDER BY subscriber_id;
```

> [!tip]- Подсказка после попытки
> Два частичных платежа — две операции.

### 06. Голосовые минуты по тарифу

_Связи и условия._

```text
#task
Для известных текущих тарифов выведи plan_id и voice_minutes исходящих событий, сортировка plan_id.
= SELECT s.plan_id, SUM(c.duration_seconds) / 60.0 AS voice_minutes FROM subscribers AS s JOIN call_records AS c ON c.subscriber_id = s.subscriber_id WHERE c.service_type_id = 1 AND s.plan_id IS NOT NULL GROUP BY s.plan_id ORDER BY s.plan_id;
```

> [!tip]- Подсказка после попытки
> Это группировка по текущему тарифу, не доказательство исторического тарифа звонка.

### 07. Активные абоненты всех тарифов

_Связи и условия._

```text
#task
Выведи plan_id и active_count всех тарифов, считая только ACTIVE. По plan_id.
= SELECT t.plan_id, COUNT(s.subscriber_id) AS active_count FROM tariff_plans AS t LEFT JOIN subscribers AS s ON s.plan_id = t.plan_id AND s.status = 'ACTIVE' GROUP BY t.plan_id ORDER BY t.plan_id;
```

> [!tip]- Подсказка после попытки
> Фильтр ACTIVE должен сохранить пустые тарифы.

### 08. Платежи без выставленных счетов

_Связи и условия._

```text
#task
Выведи subscriber_id тех, у кого есть payments, но нет invoices. По subscriber_id.
= SELECT s.subscriber_id FROM subscribers AS s WHERE EXISTS (SELECT 1 FROM payments AS p WHERE p.subscriber_id = s.subscriber_id) AND NOT EXISTS (SELECT 1 FROM invoices AS i WHERE i.subscriber_id = s.subscriber_id) ORDER BY s.subscriber_id;
```

> [!tip]- Подсказка после попытки
> Отдельные проверки фактов избегают умножения строк.

### 09. Предварительно собранная витрина

_Связи и условия._

```text
#task
Выведи subscriber_id, event_cost и paid_total всех абонентов. Сначала отдельно агрегируй call_records и payments; отсутствующие суммы 0. По subscriber_id.
= SELECT s.subscriber_id, COALESCE(c.event_cost, 0) AS event_cost, COALESCE(p.paid_total, 0) AS paid_total FROM subscribers AS s LEFT JOIN (SELECT subscriber_id, SUM(cost) AS event_cost FROM call_records GROUP BY subscriber_id) AS c ON c.subscriber_id = s.subscriber_id LEFT JOIN (SELECT subscriber_id, SUM(amount) AS paid_total FROM payments GROUP BY subscriber_id) AS p ON p.subscriber_id = s.subscriber_id ORDER BY s.subscriber_id;
```

> [!tip]- Подсказка после попытки
> У Анны два события и два платежа: сырое соединение удвоит обе суммы.

### 10. Трафик и счётчик дней

_Самостоятельный разбор._

```text
#task
Выведи subscriber_id, usage_rows, total_mb для data_usage по subscriber_id.
= SELECT subscriber_id, COUNT(*) AS usage_rows, SUM(data_mb) AS total_mb FROM data_usage GROUP BY subscriber_id ORDER BY subscriber_id;
```

> [!tip]- Подсказка после попытки
> usage\_rows считает записи, не обещает уникальные календарные дни в любой БД.

### 11. История с разницей платы

_Самостоятельный разбор._

```text
#task
Выведи change_id и fee_delta = новая monthly_fee минус старая, по change_id.
= SELECT c.change_id, new_t.monthly_fee - old_t.monthly_fee AS fee_delta FROM plan_changes AS c JOIN tariff_plans AS old_t ON old_t.plan_id = c.old_plan_id JOIN tariff_plans AS new_t ON new_t.plan_id = c.new_plan_id ORDER BY c.change_id;
```

> [!tip]- Подсказка после попытки
> Две роли одного справочника должны иметь разные алиасы.

### 12. Стоимость по типам событий

_Самостоятельный разбор._

```text
#task
Выведи service_type_id и total_cost из call_records по service_type_id.
= SELECT service_type_id, SUM(cost) AS total_cost FROM call_records GROUP BY service_type_id ORDER BY service_type_id;
```

> [!tip]- Подсказка после попытки
> Число типов в справочнике и число использованных типов могут различаться.

### 13. Общие контрольные суммы

_Самостоятельный разбор._

```text
#task
Верни event_count и total_event_cost по call_records одной строкой.
= SELECT COUNT(*) AS event_count, SUM(cost) AS total_event_cost FROM call_records;
```

> [!tip]- Подсказка после попытки
> Такие значения подходят для простой проверки учебного восстановления.

### 14. Расхождение объявленного PAID

_Самостоятельный разбор._

```text
#task
Выведи invoice_id PAID-счетов с total_amount, отличной от суммы связанных платежей. По invoice_id.
= SELECT i.invoice_id FROM invoices AS i LEFT JOIN payments AS p ON p.invoice_id = i.invoice_id WHERE i.status = 'PAID' GROUP BY i.invoice_id, i.total_amount HAVING i.total_amount <> COALESCE(SUM(p.amount), 0) ORDER BY i.invoice_id;
```

> [!tip]- Подсказка после попытки
> В корректном малом наборе результат пуст: это проверка, а не повод выдумывать строку.
