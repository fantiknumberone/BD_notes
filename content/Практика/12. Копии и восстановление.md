# 12. Копии и восстановление

[[Практика/00. Тренировки по темам|← Все тренировки]] · [[Лекции/09. Транзакции, MVCC и изоляция|Лекция 9]] · [[Лекции/14. Резервирование и восстановление|Лекция 14]]

**8 заданий для PostgreSQL** с подсказками, решениями и ожидаемым поведением.

Сначала сформулируй, какую аварию нужно пережить, сколько данных допустимо потерять и за какое время восстановиться. Команды резервирования выполняются в терминале, а контрольные SQL — в psql. Восстанавливай учебную копию в отдельную базу.

> [!info] Где выполнять
> Открой отдельную учебную базу PostgreSQL по [[Практика/База billing — устройство и запуск|инструкции запуска]]. Код ниже не запускается браузерной песочницей. Самодостаточные примеры создают объекты в схеме training внутри транзакции и завершаются ROLLBACK; запускай каждый пример отдельно целиком. Для чужого ошибочного решения откат при необходимости выполни вручную.

## 01. Контрольные показатели

Сними число абонентов, число платежей и их общую сумму перед копированием.

> [!tip]- Направление решения
> Файл копии и проверяемые данные — разные вещи.

> [!example]- Разбор и один из вариантов решения
>
> ```sql
> SELECT COUNT(*) AS subscribers_count FROM public.subscribers;
> SELECT COUNT(*) AS payments_count,SUM(amount) AS payments_total FROM public.payments;
> ```
>
> **Проверка:** Сохрани реальные значения своей копии. Для полного исходного SQL и маленького набора числа различаются.

## 02. Логическая копия

Создай custom-архив учебной базы в папке backups командами оболочки.

> [!tip]- Направление решения
> Команды оболочки выполняются вне psql.

> [!example]- Разбор и один из вариантов решения
>
> ```bash
> mkdir -p backups
> pg_dump -h localhost -U billing_user -d billing_database -Fc -f backups/billing.dump
> ```
>
> **Проверка:** pg\_dump успешно завершился, файл создан. Это ещё не доказательство успешного будущего восстановления.

## 03. Посмотреть архив

Выведи оглавление custom-архива, не восстанавливая его.

> [!tip]- Направление решения
> \--list не загружает данные в рабочую БД.

> [!example]- Разбор и один из вариантов решения
>
> ```bash
> pg_restore --list backups/billing.dump
> ```
>
> **Проверка:** Показан список сохранённых объектов. Совместимость версии утилиты нужно учитывать.

## 04. Восстановить отдельно

Подготовь новую тестовую БД и восстанови туда custom-архив.

> [!tip]- Направление решения
> Имя назначения отличается от исходной базы.

> [!example]- Разбор и один из вариантов решения
>
> ```bash
> createdb -h localhost -U billing_user billing_restore_training
> pg_restore -h localhost -U billing_user -d billing_restore_training --exit-on-error --no-owner backups/billing.dump
> ```
>
> **Проверка:** Команда восстановления завершилась успешно. После этого выполни контрольные запросы уже в новой БД.

## 05. Проверка ссылок

После восстановления проверь, не потерялись ли абоненты, на которых ссылаются платежи.

> [!tip]- Направление решения
> Проверка по PK справа различает отсутствие строки.

> [!example]- Разбор и один из вариантов решения
>
> ```sql
> SELECT COUNT(*) AS broken_references
> FROM public.payments AS p
> LEFT JOIN public.subscribers AS s ON s.subscriber_id=p.subscriber_id
> WHERE s.subscriber_id IS NULL;
> ```
>
> **Проверка:** Ожидается ноль при сохранённой целостности исходной схемы. Это не проверяет все бизнес-правила.

## 06. RPO и фактический RTO

Есть копия 02:00, пригодного WAL после неё нет, сбой произошёл 05:00, сервис вернулся 05:40. Вычисли окно потери и длительность восстановления.

> [!tip]- Направление решения
> Нарисуй временную линию.

> [!example]- Разбор и один из вариантов решения
>
> ```text
> Окно потенциальной потери — до трёх часов. Фактическое восстановление — сорок минут. Сравни эти значения с заранее заданными целями RPO/RTO.
> ```
>
> **Проверка:** Не путай возраст доступной точки данных и время восстановления обслуживания.

## 07. Слоты и отставание

Посмотри состояние слотов и потоковых реплик. Пустой результат допустим, если репликация не настроена.

> [!tip]- Направление решения
> Мониторинг связывает позиции, потребителя и свободное место.

> [!example]- Разбор и один из вариантов решения
>
> ```sql
> SELECT slot_name,slot_type,active,restart_lsn FROM pg_replication_slots;
> SELECT application_name,state,sync_state,sent_lsn,write_lsn,flush_lsn,replay_lsn
> FROM pg_stat_replication;
> ```
>
> **Проверка:** Запиши, есть ли потребители и какие позиции известны. Один active не доказывает отсутствие отставания.

## 08. План восстановления после ошибочного DELETE

Составь порядок действий для возврата до ошибочной транзакции, если есть базовая копия и непрерывный WAL.

> [!tip]- Направление решения
> Реплика могла уже воспроизвести DELETE.

> [!example]- Разбор и один из вариантов решения
>
> ```text
> Отдельная среда → восстановление базовой копии → настройка источника WAL и целевой точки → воспроизведение → проверка данных и действий приложения → осмысленное открытие для работы.
> ```
>
> **Проверка:** Назови точку остановки, доступность цепочки, проверку результата и решение о прежнем основном сервере.
