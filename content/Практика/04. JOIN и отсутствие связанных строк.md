## Следи за числом строк после соединения

INNER JOIN сохраняет найденные пары; LEFT JOIN сохраняет и левую строку без пары, дополняя правые поля NULL. Абонент может иметь много событий и много платежей: их прямое соединение способно умножить суммы. Определи, сколько строк ожидаешь на один ключ.

> [!info] Как решать
> На сайте введи SELECT и нажми «Проверить». При ошибке появятся эталон и его результат. Сравниваются значения и повторения строк; порядок важен, когда в эталоне есть ORDER BY. В Obsidian условие и эталон доступны в обычном кодовом блоке. Данные каждой страницы запускаются заново; решения не меняют исходный дамп.

## Запросы с автоматической проверкой

### 01. Текущий тариф всех абонентов

_База._

```text
#task
Выведи subscriber_id, first_name, plan_name всех абонентов с сохранением отсутствующего тарифа, по subscriber_id.
= SELECT s.subscriber_id, s.first_name, t.plan_name FROM subscribers AS s LEFT JOIN tariff_plans AS t ON t.plan_id = s.plan_id ORDER BY s.subscriber_id;
```

> [!tip]- Подсказка после попытки
> Сохрани левую сторону.

### 02. Только с тарифом

_База._

```text
#task
Выведи subscriber_id, plan_name только при найденном тарифе, по subscriber_id.
= SELECT s.subscriber_id, t.plan_name FROM subscribers AS s INNER JOIN tariff_plans AS t ON t.plan_id = s.plan_id ORDER BY s.subscriber_id;
```

> [!tip]- Подсказка после попытки
> INNER JOIN оставляет совпавшие пары.

### 03. События с именем

_База._

```text
#task
Выведи record_id, first_name, cost для каждого события по record_id.
= SELECT c.record_id, s.first_name, c.cost FROM call_records AS c JOIN subscribers AS s ON s.subscriber_id = c.subscriber_id ORDER BY c.record_id;
```

> [!tip]- Подсказка после попытки
> Зерно результата — событие.

### 04. События с названием типа

_База._

```text
#task
Выведи record_id, service_name, duration_seconds по record_id.
= SELECT c.record_id, st.service_name, c.duration_seconds FROM call_records AS c LEFT JOIN service_types AS st ON st.service_type_id = c.service_type_id ORDER BY c.record_id;
```

> [!tip]- Подсказка после попытки
> Необязательный тип не должен удалять исходное событие.

### 05. Без событий

_Связи и условия._

```text
#task
Выведи subscriber_id, first_name абонентов без call_records по subscriber_id.
= SELECT s.subscriber_id, s.first_name FROM subscribers AS s LEFT JOIN call_records AS c ON c.subscriber_id = s.subscriber_id WHERE c.record_id IS NULL ORDER BY s.subscriber_id;
```

> [!tip]- Подсказка после попытки
> Проверяй PK правой стороны.

### 06. Событий у каждого

_Связи и условия._

```text
#task
Выведи subscriber_id, event_count у всех абонентов, включая ноль, по subscriber_id.
= SELECT s.subscriber_id, COUNT(c.record_id) AS event_count FROM subscribers AS s LEFT JOIN call_records AS c ON c.subscriber_id = s.subscriber_id GROUP BY s.subscriber_id ORDER BY s.subscriber_id;
```

> [!tip]- Подсказка после попытки
> COUNT(\*) считает сохранённую строку даже при отсутствии события.

### 07. Только исходящие, но все абоненты

_Связи и условия._

```text
#task
Выведи subscriber_id, outgoing_count для всех абонентов, считая service_type_id = 1; по subscriber_id.
= SELECT s.subscriber_id, COUNT(c.record_id) AS outgoing_count FROM subscribers AS s LEFT JOIN call_records AS c ON c.subscriber_id = s.subscriber_id AND c.service_type_id = 1 GROUP BY s.subscriber_id ORDER BY s.subscriber_id;
```

> [!tip]- Подсказка после попытки
> Условие типа помести в ON.

### 08. Тарифы без абонентов

_Связи и условия._

```text
#task
Выведи plan_id, plan_name тарифов без subscribers, по plan_id.
= SELECT t.plan_id, t.plan_name FROM tariff_plans AS t LEFT JOIN subscribers AS s ON s.plan_id = t.plan_id WHERE s.subscriber_id IS NULL ORDER BY t.plan_id;
```

> [!tip]- Подсказка после попытки
> Справочник может содержать ещё не используемую запись.

### 09. Численность всех тарифов

_Связи и условия._

```text
#task
Выведи plan_id, subscriber_count для всех тарифов, по plan_id.
= SELECT t.plan_id, COUNT(s.subscriber_id) AS subscriber_count FROM tariff_plans AS t LEFT JOIN subscribers AS s ON s.plan_id = t.plan_id GROUP BY t.plan_id ORDER BY t.plan_id;
```

> [!tip]- Подсказка после попытки
> Не теряй тариф с нулём абонентов.

### 10. Сумма платежей счёта

_Самостоятельный разбор._

```text
#task
Для всех invoices выведи invoice_id, paid_total с нулём при отсутствии платежей, по invoice_id.
= SELECT i.invoice_id, COALESCE(SUM(p.amount), 0) AS paid_total FROM invoices AS i LEFT JOIN payments AS p ON p.invoice_id = i.invoice_id GROUP BY i.invoice_id ORDER BY i.invoice_id;
```

> [!tip]- Подсказка после попытки
> Связывай платежи по invoice\_id.

### 11. Без привязанного платежа

_Самостоятельный разбор._

```text
#task
Выведи invoice_id, total_amount счетов без payments по invoice_id.
= SELECT i.invoice_id, i.total_amount FROM invoices AS i LEFT JOIN payments AS p ON p.invoice_id = i.invoice_id WHERE p.payment_id IS NULL ORDER BY i.invoice_id;
```

> [!tip]- Подсказка после попытки
> Не подставляй вместо связи одинаковую сумму.

### 12. Две роли тарифа

_Самостоятельный разбор._

```text
#task
Выведи change_id, old_name, new_name по change_id.
= SELECT c.change_id, old_t.plan_name AS old_name, new_t.plan_name AS new_name FROM plan_changes AS c LEFT JOIN tariff_plans AS old_t ON old_t.plan_id = c.old_plan_id LEFT JOIN tariff_plans AS new_t ON new_t.plan_id = c.new_plan_id ORDER BY c.change_id;
```

> [!tip]- Подсказка после попытки
> Нужны два алиаса одного справочника.

### 13. Каждая комбинация

_Самостоятельный разбор._

```text
#task
Выведи subscriber_id и service_type_id всех сочетаний, сортируй по этим двум полям.
= SELECT s.subscriber_id, st.service_type_id FROM subscribers AS s CROSS JOIN service_types AS st ORDER BY s.subscriber_id, st.service_type_id;
```

> [!tip]- Подсказка после попытки
> Ожидается 8 × 5 комбинаций, это намеренное произведение.

### 14. Сверка владельца

_Самостоятельный разбор._

```text
#task
Выведи payment_id, если известный invoice_id относится к другому subscriber_id. По payment_id.
= SELECT p.payment_id FROM payments AS p JOIN invoices AS i ON i.invoice_id = p.invoice_id WHERE p.subscriber_id <> i.subscriber_id ORDER BY p.payment_id;
```

> [!tip]- Подсказка после попытки
> Пустой результат означает отсутствие этого вида расхождений в наборе.
