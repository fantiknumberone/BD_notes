# 10. Функции, процедуры и триггеры

[[Практика/00. Тренировки по темам|← Все тренировки]] · [[Лекции/10. Функции и процедуры PostgreSQL|Лекция 10]] · [[Лекции/11. Триггеры и планирование задач|Лекция 11]] · [[Лекции/12. Программирование на PLpgSQL|Лекция 12]]

**8 заданий для PostgreSQL** с подсказками, решениями и ожидаемым поведением.

Функции и триггеры выполняются на сервере PostgreSQL. Перед кодом сформулируй входы, выходы, допустимые NULL, побочные изменения и поведение при ошибке. Обработчик триггера действует в транзакции вызывающей команды.

> [!info] Где выполнять
> Открой отдельную учебную базу PostgreSQL по [[Практика/База billing — устройство и запуск|инструкции запуска]]. Код ниже не запускается браузерной песочницей. Самодостаточные примеры создают объекты в схеме training внутри транзакции и завершаются ROLLBACK; запускай каждый пример отдельно целиком. Для чужого ошибочного решения откат при необходимости выполни вручную.

## 01. Чистая функция стоимости

Создай SQL-функцию cost(seconds,rate), округляющую посекундную стоимость до двух знаков.

> [!tip]- Направление решения
> Все существенные входы переданы явно.

> [!example]- Разбор и один из вариантов решения
>
> ```sql
> BEGIN;
> CREATE SCHEMA IF NOT EXISTS training;
> CREATE FUNCTION training.cost(p_seconds integer,p_rate numeric) RETURNS numeric
> LANGUAGE sql IMMUTABLE STRICT AS $$
>  SELECT round(p_seconds/60.0*p_rate,2)
> $$;
> SELECT training.cost(90,2) AS cost_value;
> ROLLBACK;
> ```
>
> **Проверка:** Результат 3.00. Контракт этой версии не содержит проверки отрицательных аргументов.

## 02. Проверка параметров PL/pgSQL

Допиши проверку NULL и отрицательной длительности, оставив допустимую нулевую длительность.

> [!tip]- Направление решения
> Одного p\_seconds < 0 недостаточно для обнаружения NULL.

> [!example]- Разбор и один из вариантов решения
>
> ```sql
> BEGIN;
> CREATE SCHEMA IF NOT EXISTS training;
> CREATE FUNCTION training.checked_cost(p_seconds integer,p_rate numeric) RETURNS numeric
> LANGUAGE plpgsql IMMUTABLE AS $$
> BEGIN
>  IF p_seconds IS NULL OR p_rate IS NULL OR p_seconds<0 OR p_rate<0 THEN
>    RAISE EXCEPTION 'Недопустимые аргументы';
>  END IF;
>  RETURN round(p_seconds/60.0*p_rate,2);
> END;
> $$;
> SELECT training.checked_cost(0,2) AS zero_cost,training.checked_cost(90,2) AS normal_cost;
> ROLLBACK;
> ```
>
> **Проверка:** Результаты 0.00 и 3.00. Для отрицательного значения ожидается ошибка, а не молчаливый отрицательный расход.

## 03. Чтение текущего тарифа

Сделай функцию, возвращающую monthly\_fee по ID тарифа. Выбери корректную изменчивость.

> [!tip]- Направление решения
> Неподходящая IMMUTABLE может нарушить корректность оптимизаций.

> [!example]- Разбор и один из вариантов решения
>
> ```sql
> BEGIN;
> CREATE SCHEMA IF NOT EXISTS training;
> CREATE FUNCTION training.current_fee(p_plan integer) RETURNS numeric
> LANGUAGE sql STABLE AS $$
>  SELECT monthly_fee FROM public.tariff_plans WHERE plan_id=p_plan
> $$;
> SELECT training.current_fee(1) AS fee;
> ROLLBACK;
> ```
>
> **Проверка:** Для исходного Basic возвращается 300. Чтение изменяемой таблицы не является чистой функцией только от ID.

## 04. Возвращаем таблицу должников

Напиши функцию RETURNS TABLE для subscriber\_id и balance с balance < заданного порога.

> [!tip]- Направление решения
> Квалифицируй поля, чтобы не спутать их с выходными переменными.

> [!example]- Разбор и один из вариантов решения
>
> ```sql
> BEGIN;
> CREATE SCHEMA IF NOT EXISTS training;
> CREATE FUNCTION training.debtors(p_limit numeric)
> RETURNS TABLE(subscriber_id integer,balance numeric)
> LANGUAGE plpgsql STABLE AS $$
> BEGIN
>  RETURN QUERY SELECT s.subscriber_id,s.balance FROM public.subscribers AS s
>  WHERE s.balance<p_limit ORDER BY s.subscriber_id;
> END;
> $$;
> SELECT * FROM training.debtors(0);
> ROLLBACK;
> ```
>
> **Проверка:** Возвращаются все должники учебной копии. В маленьком фиксированном наборе это ID 2 и 6.

## 05. Атомарная процедура пополнения

Объедини обновление баланса и вставку истории в одну процедуру без внутреннего COMMIT.

> [!tip]- Направление решения
> Транзакция вызывающего кода охватывает CALL.

> [!example]- Разбор и один из вариантов решения
>
> ```sql
> BEGIN;
> CREATE SCHEMA IF NOT EXISTS training;
> CREATE TABLE training.proc_accounts(id integer PRIMARY KEY,balance numeric NOT NULL);
> CREATE TABLE training.proc_payments(id integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,account_id integer NOT NULL REFERENCES training.proc_accounts(id),amount numeric NOT NULL);
> INSERT INTO training.proc_accounts VALUES(1,100);
> CREATE PROCEDURE training.add_payment(p_id integer,p_amount numeric)
> LANGUAGE plpgsql AS $$
> BEGIN
>  IF p_amount IS NULL OR p_amount<=0 THEN RAISE EXCEPTION 'Некорректная сумма'; END IF;
>  UPDATE training.proc_accounts SET balance=balance+p_amount WHERE id=p_id;
>  IF NOT FOUND THEN RAISE EXCEPTION 'Счёт не найден'; END IF;
>  INSERT INTO training.proc_payments(account_id,amount) VALUES(p_id,p_amount);
> END;
> $$;
> CALL training.add_payment(1,50);
> SELECT balance FROM training.proc_accounts WHERE id=1;
> SELECT COUNT(*) AS payment_count FROM training.proc_payments;
> ROLLBACK;
> ```
>
> **Проверка:** Баланс 150, одна строка истории. Эта версия ещё не реализует идемпотентность внешних платежей.

## 06. AFTER INSERT и баланс

Создай учебный триггер списания cost для отдельной таблицы событий.

> [!tip]- Направление решения
> AFTER не означает автономность или момент после COMMIT.

> [!example]- Разбор и один из вариантов решения
>
> ```sql
> BEGIN;
> CREATE SCHEMA IF NOT EXISTS training;
> CREATE TABLE training.trigger_accounts(id integer PRIMARY KEY,balance numeric NOT NULL);
> CREATE TABLE training.trigger_events(id integer PRIMARY KEY,account_id integer NOT NULL REFERENCES training.trigger_accounts(id),cost numeric NOT NULL CHECK(cost>=0));
> INSERT INTO training.trigger_accounts VALUES(1,100);
> CREATE FUNCTION training.deduct() RETURNS trigger LANGUAGE plpgsql AS $$
> BEGIN
>  UPDATE training.trigger_accounts SET balance=balance-NEW.cost WHERE id=NEW.account_id;
>  RETURN NEW;
> END;
> $$;
> CREATE TRIGGER deduct_after_insert AFTER INSERT ON training.trigger_events
> FOR EACH ROW EXECUTE FUNCTION training.deduct();
> INSERT INTO training.trigger_events VALUES(1,1,20);
> SELECT balance FROM training.trigger_accounts WHERE id=1;
> ROLLBACK;
> ```
>
> **Проверка:** До общего ROLLBACK баланс 80. Откат отменит событие и списание вместе. UPDATE и DELETE событий требуют отдельного контракта.

## 07. BEFORE корректирует NEW

Нормализуй пробелы в имени учебного объекта BEFORE INSERT без отдельного UPDATE.

> [!tip]- Направление решения
> Вернуть скорректированный NEW — не то же самое, что пропустить строку.

> [!example]- Разбор и один из вариантов решения
>
> ```sql
> BEGIN;
> CREATE SCHEMA IF NOT EXISTS training;
> CREATE TABLE training.names(id integer PRIMARY KEY,name text NOT NULL);
> CREATE FUNCTION training.trim_name() RETURNS trigger LANGUAGE plpgsql AS $$
> BEGIN
>  NEW.name:=btrim(NEW.name);
>  RETURN NEW;
> END;
> $$;
> CREATE TRIGGER trim_before_insert BEFORE INSERT ON training.names
> FOR EACH ROW EXECUTE FUNCTION training.trim_name();
> INSERT INTO training.names VALUES(1,'  Анна  ');
> SELECT name,length(name) AS name_length FROM training.names;
> ROLLBACK;
> ```
>
> **Проверка:** Имя Анна без внешних пробелов, длина 4. Пустое имя эта версия отдельно не запрещает.

## 08. Локальное исключение

Покажи, что запись внутри аварийного блока откатывается, а обработчик позволяет продолжить внешний код.

> [!tip]- Направление решения
> Обработчик не создаёт автономную транзакцию.

> [!example]- Разбор и один из вариантов решения
>
> ```sql
> BEGIN;
> CREATE SCHEMA IF NOT EXISTS training;
> CREATE TABLE training.exception_log(message text NOT NULL);
> DO $$
> BEGIN
>  BEGIN
>   INSERT INTO training.exception_log VALUES('внутри аварийного блока');
>   RAISE EXCEPTION 'Учебный сбой';
>  EXCEPTION WHEN raise_exception THEN
>   INSERT INTO training.exception_log VALUES('обработчик продолжил работу');
>  END;
> END;
> $$;
> SELECT message FROM training.exception_log;
> ROLLBACK;
> ```
>
> **Проверка:** Осталась только запись обработчика до внешнего отката. Финальный ROLLBACK отменит и её.
