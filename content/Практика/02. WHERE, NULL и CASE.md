## Фильтр должен учитывать неизвестность

WHERE пропускает только TRUE. В этом наборе есть неизвестные email, абонент без тарифа, нулевой баланс и несколько статусов. Сначала сформулируй условие словами, затем проверь скобки у AND/OR. CASE вычисляет значение, а WHERE исключает строку.

> [!info] Как решать
> На сайте введи SELECT и нажми «Проверить». При ошибке появятся эталон и его результат. Сравниваются значения и повторения строк; порядок важен, когда в эталоне есть ORDER BY. Данные каждой страницы запускаются заново; решения не меняют исходный дамп.

## Запросы с автоматической проверкой

### 01. Активные должники

_База._

```text
#task
Выведи subscriber_id, first_name активных абонентов с балансом < 0 по subscriber_id.
= SELECT subscriber_id, first_name FROM subscribers WHERE status = 'ACTIVE' AND balance < 0 ORDER BY subscriber_id;
```

> [!tip]- Подсказка после попытки
> Два условия должны выполняться вместе.

### 02. Неизвестный email

_База._

```text
#task
Выведи subscriber_id, first_name строк с email IS NULL по subscriber_id.
= SELECT subscriber_id, first_name FROM subscribers WHERE email IS NULL ORDER BY subscriber_id;
```

> [!tip]- Подсказка после попытки
> Не используй = NULL.

### 03. Без текущего тарифа

_База._

```text
#task
Выведи subscriber_id, phone_number абонентов без plan_id по subscriber_id.
= SELECT subscriber_id, phone_number FROM subscribers WHERE plan_id IS NULL ORDER BY subscriber_id;
```

> [!tip]- Подсказка после попытки
> Отсутствие ссылки не равно plan\_id = 0.

### 04. Допустимый диапазон

_База._

```text
#task
Выведи subscriber_id, balance для балансов от 0 до 250 включительно, по subscriber_id.
= SELECT subscriber_id, balance FROM subscribers WHERE balance BETWEEN 0 AND 250 ORDER BY subscriber_id;
```

> [!tip]- Подсказка после попытки
> BETWEEN включает обе границы.

### 05. Два состояния

_Связи и условия._

```text
#task
Выведи subscriber_id, status для SUSPENDED или TERMINATED по subscriber_id.
= SELECT subscriber_id, status FROM subscribers WHERE status IN ('SUSPENDED', 'TERMINATED') ORDER BY subscriber_id;
```

> [!tip]- Подсказка после попытки
> IN выражает принадлежность списку.

### 06. Имя тарифа по шаблону

_Связи и условия._

```text
#task
Выведи plan_id, plan_name, где название начинается на S, по plan_id.
= SELECT plan_id, plan_name FROM tariff_plans WHERE plan_name LIKE 'S%' ORDER BY plan_id;
```

> [!tip]- Подсказка после попытки
> Процент заменяет и пустой хвост.

### 07. Не служебный номер

_Связи и условия._

```text
#task
Выведи record_id, destination_number событий, где номер не начинается с 900, по record_id.
= SELECT record_id, destination_number FROM call_records WHERE destination_number NOT LIKE '900%' ORDER BY record_id;
```

> [!tip]- Подсказка после попытки
> В наборе SMS направлено на 900.

### 08. Показать запасной email

_Связи и условия._

```text
#task
Для всех абонентов выведи subscriber_id и COALESCE(email, 'не указан') как contact по subscriber_id.
= SELECT subscriber_id, COALESCE(email, 'не указан') AS contact FROM subscribers ORDER BY subscriber_id;
```

> [!tip]- Подсказка после попытки
> Меняем представление результата, не исходное поле.

### 09. Категория баланса

_Связи и условия._

```text
#task
Выведи subscriber_id и category: negative при balance < 0, zero при = 0, positive иначе. По subscriber_id.
= SELECT subscriber_id, CASE WHEN balance < 0 THEN 'negative' WHEN balance = 0 THEN 'zero' ELSE 'positive' END AS category FROM subscribers ORDER BY subscriber_id;
```

> [!tip]- Подсказка после попытки
> В данном наборе все balance известны.

### 10. Скобки имеют смысл

_Самостоятельный разбор._

```text
#task
Выведи subscriber_id активных абонентов, у которых balance < 0 или email IS NULL, по subscriber_id.
= SELECT subscriber_id FROM subscribers WHERE status = 'ACTIVE' AND (balance < 0 OR email IS NULL) ORDER BY subscriber_id;
```

> [!tip]- Подсказка после попытки
> Без скобок OR может расширить набор за пределы активных.

### 11. Бесплатные голосовые события

_Самостоятельный разбор._

```text
#task
Выведи record_id, subscriber_id при service_type_id = 1 и cost = 0, по record_id.
= SELECT record_id, subscriber_id FROM call_records WHERE service_type_id = 1 AND cost = 0 ORDER BY record_id;
```

> [!tip]- Подсказка после попытки
> Ноль является известным значением.

### 12. Пополнение без счёта

_Самостоятельный разбор._

```text
#task
Выведи payment_id, subscriber_id, amount платежей с invoice_id IS NULL по payment_id.
= SELECT payment_id, subscriber_id, amount FROM payments WHERE invoice_id IS NULL ORDER BY payment_id;
```

> [!tip]- Подсказка после попытки
> Свободное пополнение является отдельным сценарием.

### 13. Фиксированный интервал

_Самостоятельный разбор._

```text
#task
Выведи record_id событий с call_date >= 2025-11-02 00:00:00 и < 2025-11-04 00:00:00, по record_id.
= SELECT record_id FROM call_records WHERE call_date >= '2025-11-02 00:00:00' AND call_date < '2025-11-04 00:00:00' ORDER BY record_id;
```

> [!tip]- Подсказка после попытки
> В браузерном наборе даты представлены строками ISO; сравниваем фиксированный формат.

### 14. Сочетание состояний

_Самостоятельный разбор._

```text
#task
Выведи subscriber_id активных абонентов с известным email и балансом >= 100, по subscriber_id.
= SELECT subscriber_id FROM subscribers WHERE status = 'ACTIVE' AND email IS NOT NULL AND balance >= 100 ORDER BY subscriber_id;
```

> [!tip]- Подсказка после попытки
> Проверь каждую часть условия отдельно.

## Как проверить себя глубже

- [ ] Объяснил, что означает одна строка каждого результата.
- [ ] Предсказал хотя бы один результат до запуска.
- [ ] Объяснил роль NULL, повторений и сортировки в сложной задаче.
- [ ] Составил собственный вариант условия и проверил его в песочнице.
