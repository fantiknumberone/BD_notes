# Учебный набор для браузера

[[index]] · [[Практика/00. Тренировки по темам]] · [[Практика/База billing — устройство и запуск|Полная база]]

В браузерных блоках используется **синтетический небольшой набор**, повторяющий названия таблиц и столбцов billing. Это не случайная выборка полного дампа и не контрольные ответы к нему. Названия и цены шести тарифов взяты из схемы курса; абоненты и события подобраны для объяснения граничных случаев. Даты зафиксированы в ноябре 2025, чтобы ответы не менялись каждый день.

| Таблица | Строк | Что показывает |
|---|---:|---|
| tariff\_plans | 6 | Тариф без абонентов, неактивный тариф |
| service\_types | 5 | Типы событий |
| subscribers | 8 | Долг, NULL email, NULL plan\_id, отсутствие событий |
| call\_records | 8 | Несколько событий у абонента, SMS и бесплатное событие |
| data\_usage | 5 | Несколько дней у одного абонента |
| invoices | 5 | Разные состояния счетов |
| payments | 4 | Частичная оплата и пополнение без счёта |
| plan\_changes | 3 | Две роли ссылки на тариф |

## Небольшая карта абонентов

| ID | Имя | Тариф | Баланс | Событий | Сумма платежей |
|---|---|---|---:|---:|---:|
| 1 | Анна | Basic | 250 | 2 | 306 |
| 2 | Борис | Standard | −20 | 2 | 0 |
| 3 | Вера | Premium | 0 | 1 | 0 |
| 4 | Глеб | Basic | 500 | 2 | 308 |
| 5 | Дина | Student | 100 | 0 | 100 |
| 6 | Егор | NULL | −50 | 0 | 0 |
| 7 | Жанна | Unlimited | 1000 | 1 | 0 |
| 8 | Зоя | Standard | 100 | 0 | 0 |

Событие Бориса с service\_type\_id = 3 — SMS, поэтому число записей call\_records и число голосовых вызовов различаются. Пополнение Дины не связано со счётом (`invoice_id IS NULL`). У Анны два платежа к одному счёту: 200 + 106 = 306.

Баланс и события здесь даны для независимых учебных запросов: полный тарифный расчёт и сверка всей истории автоматически не моделируются.

## Отличия AlaSQL от PostgreSQL

| В конспекте PostgreSQL | В браузерном setup |
|---|---|
| SERIAL / IDENTITY | Явно заданные целые ID |
| varchar, date, timestamp | STRING с фиксированными ISO-датами |
| numeric для точных денег | NUMBER JavaScript; финансовую точность не моделирует |
| Полные PK/FK/CHECK | Песочница для SELECT, не проверка всех гарантий PostgreSQL |
| MVCC, транзакции, PL/pgSQL | Изучаются в PostgreSQL, не симулируются AlaSQL |
| Полный объём исходных событий | Несколько показательных строк |

В setup поля plan\_id у абонента и invoice\_id у платежа оставлены без числового объявления типа, чтобы AlaSQL сохранял настоящий NULL, а не NaN. Это особенность браузерного примера, не рекомендация для DDL PostgreSQL.

Результаты SQL-задания сравниваются на исходном учебном наборе независимо от предыдущих запусков. Изменения в блоке `-- run` не должны портить соседнее задание. При отсутствии ORDER BY в эталоне сравнивается мультимножество строк с сохранением повторов. При наличии внешнего ORDER BY требуется тот же порядок. Числовые результаты допускают небольшую погрешность вычислений JavaScript.

Автопроверка подтверждает совпадение на этом наборе. Это не доказательство эквивалентности запросов на любых данных: запрос, захардкодивший правильный результат, может обмануть учебную проверку. Объясняй решение и проверяй граничные случаи самостоятельно.

Исходный setup также сохранён как `Практика/browser-setup.sql`, а в страницы с SQL-заданиями он включён полностью, чтобы каждая страница открывалась самостоятельно. При добавлении заданий поддерживай оба источника согласованными.
